## Планирование: анализ, идентификация проблем и поиск решений

### Проблемы

#### Проблемы с заказами
Проблемы с получением заказов. Клиенты жалуются на задержки, хотя проблема не на стороне производства.

#### Проблемы с производительностью
Проблемы с загрузкой страниц MES. Проблемы с загрузкой самих данных, заказов.

#### Проблемы с релизами и тестированием
Отсутствие автоматизации в процессе релиза. Ручное тестирование.

#### Проблемы с надежностью
Используется одна БД. Резервного копирования нет. Репликации нет.

#### Отсутствие мониторинга и диагностики
Не хватает централизованных логов, метрик по очередям и состоянию системы.
Это усложняет сопровождение и диагностику проблем.

### Инициативы

#### Улучшение наблюдаемости
Внедрить структурированные логи, трассировку, мониторинг ключевых показателей системы.

#### Автоматизировать релизы
Автоматизировать доставку и развертывание.

#### Создать сервис управления заказами
Создать отдельный сервис, который будет управлять заказами.

#### Разделить MES
Разделить MES на два сервиса: API для внешних запросов и сервис для расчёта стоимости, чтобы улучшить
масштабируемость и производительность.

#### Оптимизация инфраструктуры
Настроить резервное копирование БД. Настроить репликацию БД.

#### Ограничить B2B API
Установить лимиты для API.

#### Автоматизировать тестирование
Внедрить автотесты для E2E‑сценариев и API.

### Целевая архитектура через 6 месяцев

#### Внедрена наблюдаемость основных частей системы
Цель: Полная прозрачность работы системы для предотвращения и быстрого решения инцидентов.
Единая панель управления (Grafana/ Kibana), которая в реальном времени показывает здоровье системы,
бизнес-метрики и логи. Проблема обнаруживается ДО того, как на нее пожалуются пользователи.

#### Настроен процесс автоматического релиза
Цель: Минимизация ручного труда и человеческих ошибок при выводе изменений в продакшен.
Разработчик пушит код в Git → автоматически запускается конвейер (pipeline), который собирает,
тестирует и безопасно разворачивает изменение в нужном окружении.
Публикация в прод занимает минуты, а не часы.

#### Создан сервис для управления заками
Цель: Создать централизованное, масштабируемое и надежное ядро для ключевой бизнес-сущности.
Выделенный микросервис (Order Service) с четким API, который отвечает за весь жизненный цикл заказа:
создание, изменение, статусы, история.

#### Стабилизирована работа MES и работа с API
Цель: Обеспечить бесперебойный обмен данными с MES-системой, который является критическим для производства.
Надежная, отказоустойчивая интеграции с MES. Буферизации запросов, механизмы повторных попыток (retry),
четкие контракты API и мониторинг каждого вызова.

#### Улучшена инфраструктура со стороны работы с БД
Цель: Обеспечить производительность, отказоустойчивость и удобство управления базами данных.
Репликация, резервное копирование, мониторинг медленных запросов.

#### Настроен процесс автоматического тестирования
Цель: Обеспечить высокое качество кода и предотвратить регрессии при частых релизах.
Тесты E2E‑сценариев и API запускаются автоматически в CI/CD.

### Основные три инициативы

#### Наблюдаемость
Необходима для контроля основных бизнес-процессов. Возможность, отслеживать проблемные места
и быстро реагировать и решать проблемы.

#### Сервис для управления заками
Основная сущность системы. Необходимо строго контролировать целостность данных
и нужную скорость обработки статусов.

#### Улучшение инфраструктуры работы с БД
Необходимо для повышения стабильности работы и возможность восстанавливаться при сбоях.
